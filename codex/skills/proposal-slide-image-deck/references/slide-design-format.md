# 提案スライド設計フォーマット

この形式で `提案スライド設計.md` を作る。見出し名とコードフェンスを保つと、検証・manifest 生成スクリプトが読める。

````markdown
# {デッキ名} 提案スライド設計

## 0. 本資料の目的

{意思決定者、用途、デッキの結論}

## 1. スライド全体の方針

### 想定枚数
- {N}枚

### トンマナ
- 落ち着いた日本語 B2B 提案資料

### 画像生成で避けること
- ロゴ、機密表示、コピーライト、ページ番号を描かない
- 読めないほど小さな文字、装飾過多、未来的すぎる演出

### 生成時の共通ルール
- 16:9、重要要素はブランドフレームの safe zone を避ける
- テキストは日本語で正確に描く

## 2. スライド構成

| # | タイトル | 1枚で言い切ること | 種別 |
| --- | --- | --- | --- |
| 1 | {タイトル} | {主張} | cover |

## 3. スライド別プロンプト

### Slide 1

#### タイトル

`{タイトル}`

#### このスライドで言い切ること
{主張}

#### 構造化スライド定義 (JSON)

```json
{
  "slide_no": 1,
  "title": "{タイトル}",
  "frame_variant": "cover",
  "message": "{主張}",
  "layout": "{構図}",
  "must_include": ["{正確に描く文字}"],
  "visuals": ["{図版}"],
  "safe_zone_notes": "右上・右下・左下を空ける"
}
````

#### ChatGPT入力用完成プロンプト

```text
16:9 の日本語ビジネス提案スライドを作成してください。

デザインの方向:
- {デッキ全体のトンマナ}

レイアウト:
- {要素配置と読み順}

必ず入れたい文字:
- {タイトル}
- {正確な見出しや数値}

スライドに載せる説明文:
- {本文。短い段落または箇条書き}

ビジュアル指示:
- {概念図、表、画面モックなど}

ブランドフレーム前提:
- SPIKE STUDIO ロゴ、CONFIDENTIAL、コピーライト、ページ番号は描画しない。
- 生成後に {cover/body/body-confidential} の透過フレームを合成する。
- 右上・右下・左下の safe zone に重要な要素を置かない。

避けること:
- 小さすぎる文字、文章の密集、装飾過多、固有ブランド要素の描画。

配色と文字組み:
- {背景色、アクセント、余白、書体の方向}

仕上がり条件:
- 日本語が正しく読め、主張が一目で分かる。
```
```

JSON の `frame_variant` は `cover`、`body`、`body-confidential` のいずれかを使う。未指定なら Slide 1 は `cover`、それ以外は `body` になる。
