# S5: ワーカーからの質問や停止の通知に対応する

親が、ワーカーの質問や停止の通知を受けて、作業を続けるための判断をする。

## 質問（`ask`）

`orca orchestration check --terminal run:<Run の id>` で受信箱を読み、質問の中身を作業 Issue のコメントと照らす。

- Epic の計画と利用者が決めた内容から答えられる質問は、利用者に聞かずに答える。利用者を伝言役にしないため。答えを作業 Issue にコメントしてから、同じ全文を `orca orchestration reply --id <質問の id> --body <全文>` で返す。
- 利用者にしか決められない質問は、利用者に聞く。目的や完了の状態に関わる選択（完了の状態から項目を外すなど）、指示書の本文、`hold-merge` の PR のマージの承認がそれにあたる。返事の本文に、判断に要る中身・選択肢・おすすめとその理由を、その場で書く。指示書の本文は、入れる本文の全文を返事に書いて見せ、OK をもらう（方針に合意しても、文面が論点になることが多いため）。利用者の答えが決まるまで、`reply` を送らず、Epic の完了の状態も書き換えない。答えが決まったら、同じ全文を作業 Issue にコメントしてから `reply` する。
- 質問が新しい作業や方針の変更を含むときは、Epic の完了の状態に要るかで分ける。要るなら Epic の計画に足し（完了の状態の確認項目に紐づける）、要らなければ backlog の Issue にする。

## 停止の通知（escalation）

`worker_done` が無いまま止まったワーカーの通知は、放置しない。原因を作業 Issue のコメントから読み、続けさせる指示を作業 Issue にコメントしてから `orca orchestration send --to dispatch:<id>` で送る。続けられないと分かったら、利用者に伝える。
