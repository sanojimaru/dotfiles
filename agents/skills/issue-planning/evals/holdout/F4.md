# F4: 複数の Epic にまたがる依頼を、目標と最初の Epic に分けて渡す

## 始める状態

[F1 の共通手順](F1.md#通しの試行に共通する記録)を使います。評価用リポジトリの README には、チームがサポート定例の記録を保管していることだけを書きます。既存の目標、Epic、作業 Issue、backlog、Run はありません。デフォルトブランチの窓口とは、新しい会話を始めます。

## 実行

1. 窓口に「会議を集めて Claude Code から検索できるエージェントを作りたい」と送ります。返事を保存します。
2. 同じ窓口に、台本どおり「その成功の条件で」とだけ送ります。条件の内容や、何件を起動するべきかは追加で伝えません。
3. 目標 Issue の本文、親子関係、最初の Epic と、その親に渡した worktree およびセッションの状態を保存します。名称でなく Issue の内容と状態で判定します。

## 正しい結果

マイルストーン Issue として使う目標 Issue が 1 件あり、利用者が何をできるようになるのかをストーリーと確認項目で記録しています。その sub-issue として、最初に取り組む Epic だけが立ち、親のセッションに渡っています。親は窓口の Run から `worker-start --keep-open` で起こされ、窓口の Run の `worker-list` に出ています（窓口が次の確認で親の生死を確かめられるようにするため）。残りの候補をすべて先に Epic として立てた場合は不合格です。将来の課題を着手していない backlog として記録した場合は、その数を実行中の Epic には含めません。
