# F2: 単独タスクを起動した窓口が止まっても、片付けまで進む

## 始める状態

[F1 の共通手順](F1.md#通しの試行に共通する記録)に従って、非公開の評価用リポジトリを用意します。README の「利用手順」のリンクは存在しないファイルを指し、現行の手順書は `docs/guide.md` に置きます。Issue や Run はまだありません。リンクが正しいファイルを指すことだけを CI で確かめられるようにします。

## 実行

1. デフォルトブランチの窓口に「README の利用手順のリンク切れを直して」と送ります。窓口が単独タスクを起動したあと、Task Issue の本文と `worker-list` から Run id と子の Dispatch id を控えます。
2. ワーカーが `worker_done` を送る前に、元の窓口のセッションだけを閉じます。窓口の端末は事前に特定し、子の worktree とセッションは残します。窓口が先に完了を受け取った場合は、切り替え前の条件を作れなかった試行として種からやり直します。
3. 同じリポジトリのデフォルトブランチで新しい窓口を開始し、「次は何をする？」と送ります。以前の Run id や片付けの対象は、評価者から新しい窓口に渡しません。
4. 新しい窓口の Run、完了通知の受信、Task Issue、PR、子の worktree、利用者への返事を記録します。

## 正しい結果

新しい窓口が Task Issue の Run id で同じ Run を再開し、ワーカーの `worker_done` を受け取ります。報告と閉じた Issue、マージ済み PR を照合し、子の worktree を安全に片付けます。利用者に、直ったリンクと作業の完了を伝えます。旧窓口が片付けた場合や、別の Run を作って既存の通知を受け取れなかった場合は、このケースの成功ではありません。
